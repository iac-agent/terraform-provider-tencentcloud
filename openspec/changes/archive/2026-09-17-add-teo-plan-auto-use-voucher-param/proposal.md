## Why

The TEO `CreatePlan` API supports the `AutoUseVoucher` parameter to control whether vouchers (代金券) are automatically used when subscribing prepaid plans, but the Terraform resource `tencentcloud_teo_plan` does not expose it. Users who hold vouchers cannot instruct Terraform to automatically redeem them at plan creation time, which may leave generated orders unpaid or force manual operations via console/API, breaking the declarative workflow.

## What Changes

- Add `auto_use_voucher` (Optional, TypeString) parameter to the `tencentcloud_teo_plan` resource schema, mapped to `request.AutoUseVoucher` of the `CreatePlan` API. Valid values: `true`, `false`. Default is `false` when not set. Only effective when `plan_type` is `personal`, `basic`, or `standard` (prepaid plans).
- Wire the parameter into the `ResourceTencentCloudTeoPlanCreate` function: pass it to the `CreatePlan` API request only when explicitly configured in the Terraform configuration.
- Since `DescribePlans` response (`Plan` struct) has no `AutoUseVoucher` field, the parameter is not refreshed in Read and is treated as create-time only; changes after creation SHALL be rejected via an immutable args check in the Update function (consistent with the provider's `immutableArgs` pattern, e.g. `auto_voucher` in es/sqlserver resources).
- Add unit tests in `tencentcloud/services/teo/resource_tc_teo_plan_test.go` using gomonkey mocks to cover the Create path with/without the new parameter.
- Update the resource documentation file `tencentcloud/services/teo/resource_tc_teo_plan.md` (which does not exist yet and will be created) with the one-line description, Example Usage including `auto_use_voucher`, and Import section.

## Capabilities

### New Capabilities
- `teo-plan-auto-use-voucher-param`: Expose the `auto_use_voucher` parameter on the `tencentcloud_teo_plan` resource, passed to the `CreatePlan` API as `AutoUseVoucher`, immutable after creation.

## Impact

- **Affected files:**
  - `tencentcloud/services/teo/resource_tc_teo_plan.go` — add `auto_use_voucher` schema field, wire into Create request, add immutable args check in Update
  - `tencentcloud/services/teo/resource_tc_teo_plan_test.go` — new unit test file with gomonkey-based mock tests for Create/Read/Update/Delete
  - `tencentcloud/services/teo/resource_tc_teo_plan.md` — new resource documentation (description, Example Usage, Import)
- **API dependency:** `teov20220901.CreatePlanRequest.AutoUseVoucher *string` already exists in the vendored `tencentcloud-sdk-go` (teo/v20220901), no vendor change needed.
- **Backward compatibility:** fully backward compatible — the new parameter is Optional; existing configurations are unaffected.
- **Provider registration:** `tencentcloud_teo_plan` is already registered in `provider.go` / `provider.md`; no registration change required.
- **Documentation:** website docs are generated by `make doc` from the `.md` file during the finalize stage.
