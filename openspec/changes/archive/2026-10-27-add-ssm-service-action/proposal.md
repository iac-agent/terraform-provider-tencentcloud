# Add tencentcloud_ssm_service action

## Why

Secrets Manager (SSM) is a paid, account-level service: every SSM resource (`tencentcloud_ssm_secret`,
`tencentcloud_ssm_secret_version_v2`, ...) only works after the account has subscribed to the service
through `CreateService`. Today the provider can only *read* the subscription state
(`tencentcloud_ssm_service_status` data source), so users must open SSM manually in the console before
their Terraform configuration can succeed.

The subscription is a one-shot, side-effecting operation: it creates no object that Terraform should
track, it cannot be reverted by any API, and re-running it on an already-subscribed account returns
`ResourceInUse.ServiceAlreadyEnabled`. That is exactly the shape of a Terraform **action**
(`RESOURCE_KIND_OPERATION`), not of a managed resource.

## What Changes

- Add a new plugin-framework **action** `tencentcloud_ssm_service` that subscribes the current account
  to SSM by calling `CreateService` (`ssm/v20190923`).
- The action takes two required inputs, mapped 1:1 from the API request:
  - `pay_mode` → `CreateServiceRequest.PayMode` (`PostPay`, the only supported value),
  - `client_token` → `CreateServiceRequest.ClientToken` (idempotency token, 1-64 visible ASCII chars).
- The action surfaces the API response and the post-invocation subscription snapshot as invoke-time
  attributes that never reach Terraform state: `resource_id` and `order_id` come from `CreateService`,
  while `service_enabled`, `invalid_type`, `access_key_escrow_enabled`, `expire_time`, `qps_limit`,
  `secret_limit`, `pay_model`, `renew_flag`, `resource_region` come from a follow-up
  `GetServiceStatus` call.
- Because `CreateService` is **asynchronous** (the response explicitly states the resource may still be
  provisioning and does not mean the service is usable), `Invoke` polls `GetServiceStatus` until
  `ServiceEnabled == true` before reporting success.
- Register the action in `tencentcloud/framework/registry.go` `actionFactories` (first action of this
  repository) and list it under the SSM node of `tencentcloud/provider.md`.
- Add the inline example document and a mock-based unit test.
- **No** Create/Read/Update/Delete API surface is added: RUD are intentionally empty by design.

## Capabilities

### New Capabilities

- `ssm-service-action`: A one-shot Terraform action that subscribes the current account to Secrets
  Manager and reports the resulting subscription state.

## Impact

- New file: `tencentcloud/services/ssm/action_tc_ssm_service.go`
- New file: `tencentcloud/services/ssm/action_tc_ssm_service.md`
- New file: `tencentcloud/services/ssm/action_tc_ssm_service_test.go`
- New file: `website/docs/actions/ssm_service.html.markdown` (generated by `make doc`, never hand-written)
- Modified: `tencentcloud/framework/registry.go` (one entry in `actionFactories`)
- Modified: `tencentcloud/provider.md` (new `Action` section under the SSM node)
- SDK: uses `ssm/v20190923` `CreateService` and `GetServiceStatus`, both already present in the
  vendored SDK — no SDK upgrade or `go.mod` change required.
- Behavioural impact: none for existing resources/data sources; the action only runs when the user
  explicitly invokes it (`terraform apply -invoke=action.tencentcloud_ssm_service.<name>`).
- Not a breaking change; purely additive. Users on Terraform CLI < 1.14 cannot invoke actions and simply
  ignore this addition.
