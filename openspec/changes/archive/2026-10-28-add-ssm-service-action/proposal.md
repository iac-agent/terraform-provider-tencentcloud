## Why

Secrets Manager (SSM) is an account-level, per-region service: every other SSM resource in this provider
(`tencentcloud_ssm_secret`, `tencentcloud_ssm_secret_version`, ...) fails until the account has activated SSM.
Today there is no Terraform-native way to activate it — users must open the service manually in the console
before `terraform apply` can manage any SSM resource. SSM exposes a dedicated one-time activation API
`CreateService` (verified present in `vendor/github.com/tencentcloud/tencentcloud-sdk-go/tencentcloud/ssm/v20190923`),
which is a pure "trigger a remote side effect" call with no create/read/delete lifecycle of its own.

## What Changes

- Add a new Terraform Plugin Framework **action** `tencentcloud_ssm_service` (`RESOURCE_KIND_OPERATION`).
  - File: `tencentcloud/services/ssm/action_tc_ssm_service.go`, factory `ssm.NewSsmServiceAction()`
    (the template's "no `Action` suffix" rule cannot be honoured: the `ssm` package already declares
    `NewSsmService(client *connectivity.TencentCloudClient)`, so a same-named factory would not compile).
- Inputs (`config` block): `pay_mode` (Required, String) → `CreateServiceRequest.PayMode`;
  `client_token` (Optional, Computed, String) → `CreateServiceRequest.ClientToken`
  (auto-generated with `helper.BuildToken()` when not supplied; user-settable so that an explicit token
  can be replayed when a previous attempt's order state is unknown).
- Effect: on invoke, call `CreateService`, then poll `GetServiceStatus` until `ServiceEnabled == true`
  (the `CreateService` docs state the returned resource "may still be provisioning and does not mean
  the service is usable"), then optionally confirm `ResourceId` matches the requested pay mode.
  Conforming to the action convergence rules: poll budget from `tccommon.WriteRetryTimeout`, poll interval
  as a package-level `var`, progress via `resp.SendProgress`, `ResourceInUse.ServiceAlreadyEnabled`
  treated as "already at target state" (warn + continue), timeout error carries the last observed snapshot.
- Validation: `pay_mode` must be `PostPay` (API only supports that enum); `client_token` must be 1–64
  visible ASCII characters (`!`..`~`), no space / non-ASCII / control characters.
- No state: the action persists nothing, exposes **no** output attributes (`ResourceId` / `OrderId` are
  only logged), cannot be imported, and `destroy` does not deactivate SSM.
- Deliverables: framework registration in `tencentcloud/framework/registry.go` `actionFactories`,
  `tencentcloud/provider.md` entry, `action_tc_ssm_service.md` example, gomonkey unit test,
  `website/docs/a/ssm_service.html.markdown` produced by `make doc` (never hand-written),
  and a `.changelog` entry in the finalize stage.

## Capabilities

### New Capabilities
- `ssm-service-action`: One-time activation of Secrets Manager (SSM) for the current account/region via the
  `CreateService` API, with `GetServiceStatus` used as the convergence check; no Terraform state is managed.

## Impact

- New files:
  - `tencentcloud/services/ssm/action_tc_ssm_service.go`
  - `tencentcloud/services/ssm/action_tc_ssm_service.md`
  - `tencentcloud/services/ssm/action_tc_ssm_service_test.go`
  - `website/docs/a/ssm_service.html.markdown` (generated by `make doc`)
- Modified files:
  - `tencentcloud/framework/registry.go` (append `ssm.NewSsmServiceAction` to `actionFactories`;
    the `ssm` package import already exists)
  - `tencentcloud/provider.md` (add an `Action` section under `Secrets Manager(SSM)`)
  - `.changelog/<PR>.txt` (`release-note:new-action`), produced in the finalize stage
- Service layer: `tencentcloud/services/ssm/service_tencentcloud_ssm.go` gets a new
  `CreateSsmService` method (SDKv2-style three-piece logging + `ratelimit.Check`);
  the existing `DescribeSsmServiceStatusByFilter` is reused unchanged as the convergence read.
- SDK: no `go.mod` / vendor change is required by this proposal — `CreateService` and
  `GetServiceStatus` are already in the vendored `ssm/v20190923` package
  (the working tree already carries the vendor sync for these two APIs).
- Requires Terraform CLI >= 1.14 (native action support) and `terraform apply -invoke=...` to run.
- No breaking changes; purely additive. Existing SSM resources and the
  `tencentcloud_ssm_service_status` data source are not modified.
- Billing: `CreateService` actually places an order (PostPay). Repeated invokes place repeated activation
  requests, which is documented in the action description and example.
